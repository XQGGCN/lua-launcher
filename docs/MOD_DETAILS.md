# 查看模组声明与本地 JAR

0.12.1另有独立的[本地模组导入](LOCAL_MOD_IMPORT.md)检查与确认入口；此处的只读预览仍不能直接授权写入。

0.12.0 在“实例内容 → 模组”增加“模组声明”区域。可以读取选中的实例 JAR，也可以单独选择一个本地 JAR 预览。这个入口只读文件，不会导入、改名、启停或运行 JAR，也不会下载依赖、图标或声明里的链接。

## 查看实例中的文件

1. 选择游戏实例，并关闭该实例的游戏，等待安装、文件任务或设置保存结束。
2. 在“模组”清单中点击一个普通 `.jar` 或 `.jar.disabled` 文件。上方“条目信息”仍显示文件名、大小、修改时间和历史下载登记。
3. 点击“读取所选 JAR 声明”。没有点击时不会自动解析整个目录，也不会为了显示清单一次读取所有模组。
4. 结果显示本次文件名、外层大小、读取时间、文件摘要以及找到的声明文件。展开对应格式，查看 Mod ID、名称、版本、作者、许可、运行环境和依赖等原始声明。

`.jar.disabled` 只表示文件名具有禁用后缀；`.jar` 也不证明游戏已经加载它。声明中的名称与 Mod ID 是文件自己提供的内容，不会按名称自动匹配 Modrinth 或 BBSMC 项目。已有的启停后缀操作仍是独立操作，不会因为读取声明而自动执行。

## 预览尚未导入的本地文件

点击“只读预览本地 JAR”，在桌面文件选择窗口中选择一个普通 `.jar`。结果会标明“本地文件 · 尚未导入”，实例名仅表示此次预览的判断上下文，不表示文件已经放入这个实例。

本地预览不需要先选择清单条目。实例的 `mods` 目录为空或尚不存在时，也不会为了预览创建它；读取不会修改源 JAR、下载登记或实例配置。这里没有从只读结果直接导入的按钮，视图 ID 也不是安装能力。0.12.1通过独立入口重新检查源文件和当前实例，有限检查重复标识、禁用伙伴及已实现依赖条件，再另行确认新增导入；未知条件不强制绕过，范围见[导入说明](LOCAL_MOD_IMPORT.md)。

## 怎样阅读结果

| 显示内容 | 可以据此判断的范围 |
| --- | --- |
| 已读取声明 | 受支持的声明项完成读取和相应格式解析；不证明全部类文件、代码、依赖或游戏加载正确。 |
| 未发现受支持的模组声明 | 没有找到当前能识别的声明，可能是普通库、其他加载格式或当前未支持的文件，不能直接断定它不是模组。 |
| 声明无效或当前不支持 | 查看具体原因和读取提示。未知格式、损坏文件或超限诊断不能当作有效 Mod ID、兼容性或来源证明。 |
| 外层 JAR 文件 SHA-512 | 是这次外层文件字节的摘要。它与只读清单中的历史下载摘要分开显示，不是作者认证、签名验证或代码安全保证。 |
| 加载器声明相符 | 目前只对明确的单一 Fabric 声明格式与 Fabric 实例表示格式对应；游戏/Java 版本、环境、依赖和实际加载仍未核实。 |
| 加载器声明不匹配或未知 | 原版实例不提供识别出的模组加载方式；Fabric 不能仅因存在 Quilt/Forge 声明就视为支持。Forge/NeoForge 的历史格式及语言加载器关系、多加载格式和其他未知条件不被猜成兼容。 |

实例中的选择会按清单的名称、大小和修改时间匹配当前文件，再采样本次普通文件及路径身份，并在读取前后复验。**这不是清单生成时就保存过的历史 inode 凭据**：仅凭相同名称、大小和显示时间，不能证明点击之前文件从未被替换。需要核对一个已知文件时，应比较这次完整外层摘要与可信的发布摘要；历史登记不会因此自动变成当前字节的来源认证。

## 各种格式分别展示

- **Fabric**：读取受支持的 `fabric.mod.json` schemaVersion 1。作者、许可、环境、版本条件、依赖/建议/冲突、提供标识和内嵌 JAR 声明分别显示；不执行入口或解析依赖是否已安装。
- **Quilt**：读取 `quilt.mod.json` schema_version 1 中已实现的结构。受支持的字符串/数组及带 `id` 对象保留原条件；不能解释的组合对象显示失败或未知诊断，不保证所有 `any/all` 等结构均可读取，也不套用 Fabric 或 npm 的版本规则。`quilt.mod.json5` 属于 Quilt 的开发环境格式，本版明确不作为正式运行时模组解析；显示 Quilt 声明也不意味着 Lua 已支持创建 Quilt 实例。
- **Forge / NeoForge**：通过受限 TOML 解析器读取对应的 `META-INF/mods.toml` 或 `META-INF/neoforge.mods.toml`。一份 JAR 内有多个 `[[mods]]` 时分别显示，不合并成一个虚构 ID。语言加载器、依赖类型、版本范围、顺序和运行侧仍是声明，不表示已经判断依赖可用。
- **Manifest**：只解释 `META-INF/MANIFEST.MF` 的主节及合法续行。`${file.jarVersion}` 只在主节有唯一有效 `Implementation-Version` 时用于相应声明版本；其他占位符、后续命名节或含糊属性保持未解释。`Main-Class`、`Class-Path` 和签名相关名称仅作文字，不执行、不跟随外部文件，也不验证签名。

同一个 JAR 找到多份加载格式时，会逐份列出，不把它们拼成一个确定的兼容结论。依赖面板展示各自原始条件；“没有读取到依赖”不等于没有依赖，“提供的标识”不等于已经满足其他模组的条件。内嵌 JAR 只展示外层声明，不提取、递归读取或执行。具体格式、一手文档与解析器版本见[模组元数据格式说明](MOD_METADATA_FORMATS.md)。

## 停止、切换与限制

“停止读取”只取消当前操作，界面会等原始读取或文件选择工作实际结算后再解除忙碌状态。文件选择窗口尚在等待时，停止请求不保证替你关闭系统窗口。切换实例、条目或刷新后，先前请求的结果和错误不会填入新上下文；更改选择期间可能先显示“正在结束先前选择的读取”。同实例的后缀改名、刷新及其他冲突任务需等待读取结束。

读取有明确上限：外层文件最多 512 MiB、中央目录 16 MiB、20,000 个 ZIP 条目，单份选定声明 256 KiB、声明合计 1 MiB；元数据另有深度、节点、字段、模组/依赖条数和结果体积预算。全局最多两个模组读取，同实例同一时间只读一个，整体采用 30 秒合作式预算；同步解析并不是可硬实时中断的执行器。

实现不会把整个 JAR 放进内存或解压到磁盘。只对选定声明项解压并核对实际大小/CRC，另行流式计算外层摘要；其余类文件没有逐项解压验证。ZIP64、加密、多卷、危险或含糊的条目布局等不在当前范围时会明确返回不支持或无效。超限不代表文件恶意，也不能通过忽略提示来获得已验证结论。

本文描述 0.12.0 的只读实现范围，不表示已完成真实系统文件选择窗口、第三方模组、Java/游戏加载、完整三平台实机或当前提交 CI/公开发行验证。原生 IPC 与测试替身等实际执行证据，分别以该版本开发及审查日志为准。
