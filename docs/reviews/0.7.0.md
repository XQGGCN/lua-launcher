## REVIEW-070-01 / P2：切换来源后旧请求仍能签发新 revision

原 Core 只在请求开始清除旧 token，并检查实例 mutation generation。它没有单独记录当前世界视图来源。因此同一世界先发起主文件读取并挂起，再切旧副本；旧副本返回后，较早主文件请求仍能正常返回并签发新的种子读取凭据。两次都是只读，没有触发实例 mutation，原守卫无法区分过期视图。

作者新增明确 deferred 交错：main 挂起→old 挂起→old 完成→main 完成，预期较早请求拒绝。修复前实际运行出现 `Missing expected rejection`，不是仅源码推测；没有读取真实世界或依赖墙钟时序。

集成者加入有界 per-world view 身份（最多 64）：同来源同键 pending 共享当前 view，来源变化或新的 fresh read 替换 view；完成时和 seed reveal 均核对该身份，mutation/退出清理 view 与 token。修复后原红灯变绿，且同键并发仍只调用一次 reader、返回独立 DTO 与有效的各自 revision。已签凭据刷新失效、挂起 reveal 迟到、TTL、跨实例和完整安装/设置周期后的旧读取均由 19 项 Core 测试覆盖。

## 后端独立检查

- NBT 根、0–12 类型、signed scalar/long、list/compound、重复键、未知完整子树、截断和尾部数据；大小、深度、标签、字符串/数组累计预算覆盖未知字段，不构建任意 NBT 树。canonical MUTF-8 的窄契约与 Java surrogate 单元被明确记录。
- gzip CRC/截断、多个 member 共享展开限额、流错误和取消销毁；压缩字节有界，FD 在读、解析、异常和取消后关闭。解析失败不发布前面已读的名称或种子。
- 固定 `game/saves/<basename>/<source>`；basename/ID/字段严格验证，祖先/链接/大小写/NFC、file descriptor 和解析前后身份复核。替换、同 inode 修改和世界目录替换都不会发布已变快照。
- 默认 Core DTO 显式白名单，没有 seed、私有指纹、Player 或绝对路径。未知异常统一安全错误，无原始值日志。reveal 重新读取当前 source，核对相同 revisionKey 与视图、TTL、实例 generation，精确十进制 int64 另验。
- 同键 pending 去重并复制结果；两个全局读槽先登记，取消等待忽略 signal 的 worker 真正结算才释放；主进程取凭据前同步失效旧读取。安装、运行和设置互斥，完整操作结束后旧读取仍失效。
- error 实例只读允许且不调用模组恢复检查，不清 marker，不保存 launcher.json，不触发原始值日志。真实临时夹具证明主/旧文件、状态和内容不写入；mtime/ctime/inode 等与字节核对，未把 atime 纳入保证。

原始 Core 临时文件测试和注入故障是可复现边界，不代表完整现实磁盘故障、任意同用户对抗竞态或真实游戏保存过程都已验证。

## 格式和未验边界

官方 26.1 公告与维护者补丁确认了难度/硬核嵌套和独立数据文件迁移。当前支持选定文件内的旧字段与新的 difficulty_settings；同字段两种布局矛盾时不拼接。独立 seed/clock 文件、Player、region、数据包和图片都不读。

NBT 字符串只接受 canonical Java DataOutput 形式，比宽松 DataInput.readUTF 的输入集合小。五秒预算为合作式，不能打断已提交的内核文件调用；字节/结构上限属于产品限制，不代表合法世界最大值。安全身份复核不是运行中世界的一致快照，应关闭外部游戏。

没有已授权的真实游戏生成世界样本；旧库存人工 fixture 没有作为实机证据。真实两版本样本、原生 Electron、当前提交 Windows/Linux/macOS CI、签名/公证、公开发布和当前纯在线游戏仍待，不应移除这些限制。
