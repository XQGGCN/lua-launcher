## 结论

已发现的两项 P2 均由集成者源码定位、模块作者实际红灯并修复，独立作者最终源码复核和 53/53 定向合跑通过。已读模块/Core/IPC/UI 范围没有已知未解决的实质 P1/P2。当前结论不代替真实世界、跨卷、Windows/Linux 或原生验证。

## REVIEW-071-01 / P2：取消覆盖提交不明

集成者发现外层 catch 只看 signal.aborted，可将内部 RECOVERY_REQUIRED 改成 AbortError。模块作者实际注入 `link` 完成后返回 EIO、随后读取发布凭据返回 EACCES，同时发起取消；原结果实际误报 AbortError，修复后保持 RECOVERY_REQUIRED。该情况可能已经生成完成凭据，不能只告诉用户“已取消”。全部资料必须保留并要求检查。

独立 Core 用忽略 signal 的 worker 返回 RECOVERY_REQUIRED，验证 task 保持 error、无成功 result，锁在 worker 结算后释放，不被取消分支吞掉。Core 及模块最终独立重跑通过。旧红灯执行者为模块作者，不是本记录作者。

## REVIEW-071-02 / P2：丢失 link 回应且无法核对，被降为普通 IO

同一个实际 link→EIO + 发布凭据 EACCES 注入，不发送取消时，原代码在复核失败后回抛最初 link 错误，表现为 IO_ERROR。集成者指出此时不能证明未提交。模块作者确认实际红灯，并修为保守 recovery 分类；明确提交凭据不存在时才允许视为未提交。成功且身份/字节可以证明时仍应完成，不因回应错误或迟到取消回滚。

最终独立重跑包含该回归、完成成功及失败保留测试，均通过；这不是模拟错误就声称真实网络文件系统已测，注入只证明代码对不确定回应的分类。

## 明确剩余边界

- 所有失败/取消残留都保留，可能占用大空间；不自动清理、续传、ZIP 或恢复，手工重建测试不是产品恢复功能。

- 真实授权世界、实际不同卷、Windows/Linux 文件系统、原生桌面、当前提交 CI、签名/公证、公开发布和当前纯在线游戏仍未验。公开仍为 0.3.0；浏览器登录恢复与旧版源码上传不是当前版本发布证据。
