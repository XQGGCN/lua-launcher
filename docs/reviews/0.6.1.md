## 已修复发现

### REVIEW-061-01 / P2：数组形式的依赖类型绕过外部处理分支

原代码用 `String(dependency_type)` 判断枚举，却保留原始值；JSON 中的 `["required"]` 能通过字符串检查，后续严格等于 `required` 的分支不成立，可能把有必需依赖的发布误当作可直接安装。现先要求字段确为字符串，再检查枚举；未知结构直接拒绝。

由源码分析发现，未运行修复前红灯。独立目录测试覆盖数组 required/incompatible、未知类型和损坏依赖；正确的 required/incompatible 保持官网获取。

### REVIEW-061-02 / P2：把合法项目短名称当成严格项目 ID

搜索结果的 slug 原先复用只允许字母数字、下划线和短横线的 ID 校验，带点、加号等合法短名称会使整个搜索失败。现将显示用 slug 作为受长度/控制字符约束的文本处理，真实项目身份仍使用严格 ID；官网链接不使用该字段来决定本地路径或下载目标。

由源码分析发现，未运行修复前红灯。独立测试保留 `resource.pack+32x` 等合法短名称，同时拒绝损坏计数、重复项目与不可信图片来源；搜索错类型处理后来按 REVIEW-061-07 调整为明确省略，安装类型检查不放宽。

### REVIEW-061-03 / P2：响应及文件句柄在早退路径未释放

原下载流程在取得 body reader 后、进入 try/finally 前打开文件及读取句柄状态；打开或 stat 失败可能留下 HTTP body/reader，后者还可能遗留文件句柄。fetch 返回后的取消或响应 URL 校验异常也缺少 body 清理。

现将可选文件句柄及 reader 放入统一释放边界；响应校验失败主动取消 body，取消监听唤醒已经等待中的 reader。实现者新增 payload-open 失败、非法响应 URL 和忽略信号的挂起流测试，独立执行通过。原问题为源码发现，不声称运行过旧版失败测试。

### REVIEW-061-04 / P2：新硬链接在首次验证前被同 inode 编辑，回滚可能删掉编辑

当新目标已通过 hard link 创建，但首次 `verifyFile` 尚未成功赋值 `targetIdentity` 时，外部原位写入能使校验失败；原回滚仅凭 inode 相同删除目标，没有确认内容仍属本任务。现该分支还要求大小和修改时间保持 payload 的状态，否则返回 `ResourceInstallRecoveryError` 并保留文件和暂存资料。

问题由源码交错分析提出；实现者同期修复并补精确回归。作者随后独立执行一次临时目录注入：真实 `fs.link` 后 `fs.writeFile` 写入 `external user edit`；当前代码返回恢复错误，目标编辑和暂存目录均保留。该独立注入已包含修复，未运行旧版红灯。另复核暂存登记 inode/字节在提交前再次校验、旧登记不覆盖、既有相同文件不删除，以及成功登记 rename 后取消不回滚。

### REVIEW-061-05 / P2：资源下载期间首页启动入口漏锁（协作 UI 发现）

资源任务没有改变实例的 ready 状态，首页原有按钮可能仍允许点击启动。后端互斥保护仍在，但界面会显示错误的可操作状态。现按钮按实例资源任务禁用并显示“资源下载中”，通用 `run` 入口同时检查同步 `resourceLocks`，覆盖状态更新前的窗口。协作审查者完成源码复核；本记录不把它写成作者亲自浏览器或真实启动测试。

### REVIEW-061-06 / P2：A 安装完成使 B 的内容页重新挂载

原安装成功处理使用全局递增的内容 key，A 后台任务完成也会重挂载正在查看的 B，导致分类、分页或详情状态被重置。现按实例 ID 更新 refresh revision，组件只接收当前实例的变化；后台 A 完成不会强制重建 B。协作审查者已源码复核；集成者测试桥另验证 A 后台完成时 B 世界分类和已填搜索不丢失。作者没有重复浏览器操作。

### REVIEW-061-07 / P2：真实搜索混入其他类型与简介换行使整页失败

集成者的生产 Core 搜索首先发现 BBSMC 光影页失败。作者随后两次只读请求相同官方 API 条件（shader、iris/optifine、MC 1.20.1、20 条）：返回 20 个不同项目 ID，其中 `RBkrnJx3` / Glowing 明确为 resourcepack，另两项光影简介包含普通换行。前者触发整页类型拒绝；仅处理混合类型后，通用文本控制字符限制仍会误拒合法简介。原始来源为 [BBSMC 公开 API](https://api.bbsmc.net/v2/search?query=&facets=%5B%5B%22project_type%3Ashader%22%5D%2C%5B%22categories%3Airis%22%2C%22categories%3Aoptifine%22%5D%2C%5B%22versions%3A1.20.1%22%5D%5D&offset=0&limit=20&index=downloads)，这是本次观察，不保证索引永久不变。

现先严格验证项目 ID 与类型字段结构，缺失/损坏类型和重复 ID 仍拒绝；明确属于其他类型的搜索项仅省略，不改标为当前类型。结果报告 `omittedHits`，界面说明总数和页宽仍来自上游；即使本页全部被过滤，也保留按上游 limit 推进的分页。安装时仍重新取得项目并严格核对类型。简介单独允许普通换行/回车/tab，NUL、其他非法控制字符和超长文本仍拒，身份、标题、文件名等不放宽。

新增两项独立回归，catalog 从 21 增为 23。本次实际执行过过滤修复前 **22 通过 / 1 失败**，失败即混合页整页拒绝；当时简介处理已经修好，不能声称该子问题也跑过旧版红灯。最终 catalog 23、事务 30、Core 17 共 **70/70** 通过，类型检查通过。混合页、全过滤页、安装类型不变及描述/身份边界均覆盖；集成者已在此晚修后重跑全仓 347/347 和构建通过，最终未签名 macOS ARM64 DMG/ZIP 的版本、架构及 SHA-256 核对通过。

## 定向覆盖与残余边界

- 元数据与文件分别限定当前来源的 API/CDN；逐跳检查、4 MiB 元数据、严格 UTF-8、SHA-512 必需/可选 SHA-1、512 MiB ZIP 上限，以及跨平台 basename、链接/目录与登记校验均有定向测试。
- 安装前重新核对项目类型、版本、所选文件名/hash；明确的 primary 决定主文件；无 primary 时只接受唯一主 ZIP，附带资源包或非 ZIP primary 不回退到其他 ZIP。资源包只选 minecraft，光影只选 Iris / OptiFine；声明兼容不等于本机已有渲染前置。
- 默认安装器在临时实例中实际落盘两类 ZIP；不解压、不改 options 或 launcher 状态，复用不重复下载。登记来源/hash 是历史记录，改坏 ZIP 后只读清单仍明确保留历史 receipt，不认证当前字节。
- Core 同步登记互斥、全局四任务上限、operation ID 绑定取消、退出取消、worker 结算再释放、提交后完成优先、恢复失败状态落盘、安装前后旧扫描失效已测试。
- 无覆盖 link 和原子 ledger rename 提供应用层事务；这不等于任意断电或恶意并发文件系统攻击下的完整事务保证。不能安全回滚时需要人工检查保留的恢复资料，不自动移除其目标。
- 集成者已完成下述测试桥范围，原生与全部辅助功能矩阵不能据此通过；原生 Electron、当前提交 Windows/Linux/macOS CI、签名/公证、公开 Release、完整 Microsoft 登录和游戏均未验收。BBSMC 实际 CDN 仍可能需要官网验证，不能绕过。

协作 UI 审查者还通过独立源码/SSR 注入复核全过滤页 offset 0/20/480 的空态、说明、页码和前后按钮，未执行真实浏览器；集成者随后测试桥确认全过滤首页仍能下一页到有效项目，并能上一页返回。

新增测试已核实纳入 `package.json` 的标准测试入口。公开基线仍为 0.3.0；不能借用旧 CI、旧安装包或历史离线游戏结果证明本版本通过。
