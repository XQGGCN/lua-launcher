## 已修复问题

**P2：打开实例文件夹时丢弃 Promise，使等待状态和跨实例错误隔离失效。**

原 App 回调使用 `onOpenFolder={id => { void run(...) }}`，立即返回 `undefined`。`run` 还会自行捕获异常并显示全局提示。组件中的 `await onOpenFolder(...)` 因而无法等待实际操作，按钮的忙碌状态立即解除，局部错误提示无法收到异常。若先操作实例 A、再切到 B，A 的迟到失败仍会通过全局提示出现。

修复后的 App 直接返回 `call<void>('openInstance', id)`；组件属性契约为 `(id: string) => Promise<void>`。`openFolder()` 使用请求序号和当前实例 ID 守卫处理成功、失败和结束状态；切换实例或卸载时会使旧序号失效。已复核这两处源码，确认 Promise 与异常完整返回组件。

建议交互验收：延迟 `openInstance` 的完成，确认按钮保持忙碌且不能重复点击；同实例失败后显示可重试错误；切到另一实例或离开页面后，旧请求失败不会污染新页面。这部分由主线程的隔离浏览器桥接验收执行，结果应单独记录，不能当作原生文件管理器测试。

## 已核对的界面行为

- **请求隔离**：清单请求同时检查递增序号及包含实例 ID、分类、安装状态的键。切换分类、切换实例、重新读取和卸载都会使旧请求失效。返回的实例 ID 和分类还会再次校验；旧请求的错误和 `finally` 不会结束新请求的加载状态。
- **安装与运行状态**：安装中清除旧清单、停止发起新扫描并显示说明；安装状态解除后重新读取。运行中允许只读查看，同时提示清单可能随游戏变化。扫描错误有重试入口，未把错误或截断的空结果表述为实际目录为空。
- **来源和格式语义**：“曾登记来源”明确为历史记录，不证明当前字节、完整性、兼容或实际加载。JAR/ZIP 被描述为文件后缀；`.disabled` 仅显示禁用后缀。目录不报告递归大小。存档详情明确没有解析 NBT，不把文件修改时间等同于最后游玩时间。
- **筛选与分页**：文件名筛选只作用于本次已读取的条目。截断时显式提示非完整清单。排序、筛选、分类切换和翻页会清除旧条目选择；每页最多 100 项，页数变化时会限制当前页索引。
- **键盘与标签**：分类采用 tab/tabpanel 关系和 roving tabindex，支持左右方向键、Home、End。搜索、实例选择和排序有标签；文件详情选择使用原生按钮。相关控件有可见焦点样式。实际读屏和浏览器键盘交互仍需界面验收。
- **长文本**：文件名、相对路径、来源 ID 和警告使用文本渲染；详情和文件名允许长词换行，表格容器允许横向滚动，窄屏工具栏可换行。这里只核对 CSS 约束，未将其描述为所有窗口尺寸的视觉测试通过。
- **只读与浏览器状态**：列表没有删除、启用、禁用、移动或解压动作。打开文件夹只传实例 ID。浏览器预览不发起本地清单请求、不生成示例文件和虚构数量，并明确说明需要桌面版。
