## 已修复发现

### REVIEW-060-01 / P2：旧扫描跨越整个安装周期后仍可发布

原接线仅在扫描开始和结果返回时检查 `installs.has(instanceId)`。如果扫描等待期间某次安装已经开始并结束，安装控制器会在结果检查前移除；旧扫描于是仍可能返回安装前的文件清单，或把不同安装阶段的文件信息和历史账本组合显示。开始/结束两次检查不能识别中间发生过的安装。

此问题由源码交错分析发现。回归测试落盘前主实现者已经修复，因此没有实际执行修复前的失败测试，不能称作运行复现红灯。

修复在 `install` 和 `installMod` 同步登记安装控制器后，立即取消该实例全部已有库存扫描。扫描任务保留到 worker 结算再释放，并在发布结果前检查取消信号；即使扫描器忽略取消、安装已经完成，旧结果也不会成功返回。取消以实例 ID 为界，不影响另一实例。

确定性验证使用临时目录及注入 fetch：先挂起旧扫描，再通过真实 `Core.installMod` 完成模拟资源元数据读取、校验下载、JAR 和账本落盘；确认新文件存在后才让旧扫描返回空清单。旧请求必须拒绝，新请求可以重新扫描。测试没有真实联网，也没有执行所写入的测试 JAR。另一个用例覆盖安装仍进行时的取消，以及其他实例扫描不受影响。

### REVIEW-060-02 / P2：文件夹回调丢弃 Promise（协作发现）

界面审查者发现 App 的文件夹回调丢弃异步 Promise，使组件不能持续显示等待状态，并可能让实例 A 的迟到失败在切到 B 后显示为全局错误。主实现者已改为返回原调用 Promise，由组件按实例 ID 和请求序号处理结果。具体源码复核及限制见 [UI 审查记录](./0.6.0-ui.md)；本记录作者没有重复执行该界面审查或浏览器交互。

## 边界检查

- Core 只接受已存在实例 ID 和四种枚举类型。游戏目录及 `managed-mods.json` 路径由主进程生成；renderer 不能通过库存接口提供任意路径。`worlds` 固定映射到 `saves`。
- 扫描仅枚举固定目录的一层条目，读取文件类型、大小及修改时间。不会创建目录、迁移账本、读取 JAR/ZIP 内容或解析世界 NBT；目录没有伪造递归大小。
- 逐级检查目录祖先，拒绝普通符号链接/junction；仅特许模块中明确列出的 macOS 系统临时目录别名。枚举前后检查资源目录身份，跳过条目链接及非常规文件，对权限/消失/截断情形给出错误或警告。
- 来源账本读取限制为 1 MiB，校验普通文件、打开后的身份和读取一致性，使用可用平台上的 `O_NOFOLLOW`。历史无前缀项目 ID 仅在内存解释为 Modrinth，不重写账本。大小写/NFC 冲突、多份来源声明和截断结果不自动归属。
- 来源字段仅表示曾经登记的来源，不证明当前字节、兼容性、完整性或实际加载；`.disabled` 仅表示文件名后缀，JAR/ZIP 仅表示扩展名。
- Core 同一实例/类型共享在途任务，每位调用者取得独立深克隆；全局最多四个唯一扫描。失败、取消和完成后释放槽位；取消不提前删除仍在运行的任务。
- 退出会传递取消信号，晚到结果不能发布。安装开始会取消同实例已有扫描，安装期间的新扫描会被拒绝。
- main 检查调用窗口及 frame 来源，preload 只增加枚举方法。此次是源码检查和 Core 测试，未将其表述为原生 Electron IPC 实机验证。

## 剩余验证与限制

- 扫描上限为 5000 个目录条目和 5 秒协作式时间检查。已经提交给操作系统的 metadata 调用不能强制中断，卡住的文件系统可能超出该时间；扫描不会提前释放并发槽位假装已经结束。
- 文件系统是实时可变的，清单是一次观察，不是锁定所有外部程序的原子快照。安装器自身的交错通过取消保护；不能据此宣称抵御任意本机恶意进程持续替换目录的全部竞争情形。
- 原生 macOS 界面仍受设备锁定限制，当前版本的 Windows/Linux/macOS CI 与安装包实机流程未验。Git 连接限制尚未解除，不能把本地结果称为远端提交、公开发布或官网更新成功。
- Microsoft API 仍待批准。本轮未执行真实认证或游戏启动；真实游戏中的模组加载、资源包/光影启用、世界读取均不由这份库存测试推导。
- 本轮仅完成只读库存。启用/禁用、删除、移动、导入、更新、冲突解析和世界编辑不在本轮实现或验收范围内。

最终提交与公开发布完成后应追加对应证据；不得用本地模拟测试代替尚未完成的原生、跨平台或真实游戏验收。
