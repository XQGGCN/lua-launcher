# 启动器窗口偏好

0.15.0 的窗口偏好已在本地完成实现与有限范围独立审核，当前公开下载仍为 0.10.2。这里调整的是 Lua 启动器外框，不是 Minecraft 游戏的分辨率、全屏或实例 JVM 参数。验证结果按文末记录；未通过的系统场景不以界面预览代替。

## 调整方式

在“设置 → 启动器窗口”中选择标题栏、是否记忆窗口，以及恢复窗口摆放。这里的选项单独保存，不必点击页面底部的“保存设置”；下方尚未保存的游戏设置草稿继续保留。

| 选项 | 生效方式 | 范围 |
| --- | --- | --- |
| 融合标题栏 / 系统原生标题栏 | 保存偏好，下次正常创建启动器窗口时应用；当前窗口继续使用原样式 | macOS / Windows；Linux 本版仅原生标题栏 |
| 记住窗口大小、位置与最大化状态 | 下次打开时使用已保存的普通外框和最大化状态 | 主进程已知位置的环境；Linux 默认保守分支只记最大化 |
| 恢复默认大小和位置 | 明确点击后立即作用于当前 Lua 窗口，按可用工作区恢复默认大小和可见位置 | 位置由桌面环境管理时只设置默认大小，由桌面环境安排位置 |

标题栏切换不会主动重启、销毁或重建当前窗口，也不会为了生效打断正在执行的任务。在 macOS 正常关闭最后一个窗口后，再通过应用激活创建的新窗口会读取偏好；Windows / Linux 按既有关闭行为在下次启动时创建。关闭整个应用与只关闭窗口的行为没有新增开关。

页面分别显示“当前窗口”的实际样式和已保存、待下次窗口创建的选择。保存中等待实际请求结算，期间不能重复修改；读取或保存出错会显示错误，不把提交失败显示成新值已保存。主进程发出的较新状态和错误优先于迟到的旧读取结果。浏览器预览不能读写真实窗口偏好，控件明确不可用，不伪造本地持久化。

0.15.0没有界面缩放设置；0.15.1已单独完成本地[有限界面缩放](INTERFACE_ZOOM.md)与对应证据，只按当前有效平台/标题栏开放档位，不把本节0.15.0原生结果借作缩放证据。字体、密度、背景、透明、毛玻璃、自绘窗口按钮、托盘和任意坐标控制也未加入。

## 平台差异

macOS 的融合样式使用 Electron `hiddenInset` 与既有交通灯位置；Windows 使用 `hidden` 和系统 `titleBarOverlay`，并仅在当前确实为融合样式时同步深浅颜色。原生样式使用系统外框，不启用覆盖标题栏；界面不渲染额外拖动罩层，也不继续套用融合样式的顶部留白。融合样式没有另造一套关闭/最大化按钮。

Linux 本版统一使用原生标题栏。除显式 `--ozone-platform=x11` 外，主进程保守地将普通窗口大小和位置交给桌面环境，只记忆最大化状态；这不是检测到了 Wayland，也不把环境变量、默认后台或返回的 `0,0` 当可靠坐标。显式 X11 分支可采用普通几何记忆，但不能据此宣称已经完成 Linux/X11 原生实测。

位置交由桌面环境管理时，页面显示“记住最大化状态”和“此环境由桌面环境管理窗口位置”。恢复按钮只承诺设置默认大小，不承诺把窗口移动到某个坐标。无论哪种平台，最小化、隐藏和全屏都不作为下次启动应恢复的状态；恢复大小前需要先退出启动器全屏。

## 尺寸和多屏纠正

几何使用 Electron 的 DIP 外框和 `screen.workArea`，不乘显示器缩放因子，不把物理像素、CSS 像素与外框大小混用。默认外框为 1240×840，常规最小值 880×640；工作区更小时将有效最小值和大小一起限制到工作区，低于常用面积时不承诺所有内容能同时显示。

主进程最多处理前 64 个工作区，过滤无效矩形。保存坐标是有限整数，绝对值上限为 1,000,000 DIP；有效负坐标副屏可保留。目标屏幕优先取与原普通窗口交集最大的可用工作区，平局确定处理，完全离屏则回到主屏或首个有效工作区；没有有效工作区时交给系统默认构造，不制造坐标。

已知普通窗口只有在顶部两端和足够拖动宽度可达、且外框受可用工作区覆盖时才原样保留，否则限制尺寸并纠正位置。该策略是有限几何规则，不等于实际拔插显示器或所有窗口管理器的行为保证。显示器移除和工作区变化合并后检查当前窗口；最大化时保持最大化，不为了纠正强行还原。普通外框与最大化状态分开保存，避免将最大化后的大矩形当作普通大小。

记忆开关关闭后，不再记录新的窗口摆放；下次创建按默认大小和当前工作区处理。恢复摆放不改变已选标题栏、Minecraft 游戏窗口设置、实例文件或账户。

## 本地存储与失败处理

配置保存在 Lua 数据目录中的独立 `window-preferences.json`，不复用 `launcher.json` 的游戏设置或 Microsoft 会话。普通窗口setter仍只接受受限样式和布尔开关；0.15.1的缩放另走有限IPC，不能夹带到此setter。renderer不能提交原生文件路径、显示器列表、任意坐标、窗口构造选项或 JavaScript。原有主进程可信调用来源、preload 白名单、隔离和权限限制继续有效。

| 限制 | 当前实现 |
| --- | --- |
| 配置 | 0.15.0为schema1；0.15.1已知schema1/2联合读取、惰性演进，见[缩放回退边界](INTERFACE_ZOOM.md)；16KiB和受限字段保持 |
| JSON | 有界节点和深度；拒绝重复键、未知字段、不完整值和不支持 schema |
| 路径和文件 | 固定配置名、普通文件、祖先与 FD 身份复核，不沿不受支持链接读写 |
| 准备写入 | 同目录私有 `wx` 文件、短写循环、sync、独立大小/字节/hash 读回与发布前复查 |
| 首次创建 / 更新 | 首次无覆盖 hardlink；已有配置在核对原身份后替换，再读回当前文件确认结果 |
| 准备文件保留 | 仅当前操作的身份、大小和 hash 全部匹配时清理；未知或历史文件保留 |
| 当前进程失败预算 | 本次 store 累计 32 个无法安全清理的准备文件后停止新的持久写入；不是历史文件总数或全局磁盘容量上限 |

坏 JSON、未知 schema、超限、链接、权限或目录/文件身份变化都会保留原件，采用安全默认值或上次已提交状态，并显示非致命诊断。结果不明确时暂停继续写入，不自动把坏配置当空文件覆盖，也没有自动修复、历史清扫或恢复向导。

普通移动/调整大小合并保存，写入期间的新变化在结算后继续处理。关闭当前窗口、创建后继窗口和退出阶段等待窗口保存，但每次等待最多约 2 秒：等待正常结束本身也不替代配置返回的诊断；超时返回失败只表示不再无限等待，**不表示保存成功，也不取消底层 I/O**。迟到 I/O 仍可能完成或留下私有准备文件。旧窗口控制器不再发布到或操作后继窗口；这不是强杀任意挂起系统调用、断电耐久或整个启动器所有任务退出等待的保证。
