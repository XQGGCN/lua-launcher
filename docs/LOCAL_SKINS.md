# 本地皮肤收藏与2D预览

0.14.0已在本地实现“本地皮肤”页，等待发行，公开下载仍为0.10.2。这是独立于账户的本地PNG收藏库，未登录也可以使用；不创建游戏身份，不上传图片，不改变当前账户皮肤、头像或披风。

## 使用方法

1. 打开“本地皮肤”，点击“选择 PNG”，在原生文件选择窗口中选取自己的图片。
2. 检查图片和正反面预览，填写收藏名称和标签。新图片必须明确选择经典 Classic 或纤细 Slim，不能根据透明像素自动推断保存模型。
3. 点击“加入本地收藏”。准备图片和正式收藏是两步操作；选择文件或调整预览并不会自动入库。
4. 收藏后可按名称或标签搜索、筛选标签、每页24项翻页。列表只读取收藏信息，选中后才读取该图片，不预读整库PNG。
5. 选中收藏后可改名、改标签或保存模型，再点击“保存收藏信息”。也可“导出 PNG”或“移出收藏”。

名称上限64个码点，标签最多8个、每个24个码点，用逗号分隔。后端对原始输入和NFC规范化/trim后的结果均检查长度；界面也检查规范化结果。标签按不区分大小写判断重复，控制字符和非法文本会拒绝。Unicode规范化可能改变码点数量，不能仅以输入前长度判断可保存。

## 布局、模型和透明度

| 图片布局 | 当前模型 | 预览内容 |
| --- | --- | --- |
| 64 × 64现代布局 | 经典 Classic、纤细 Slim，玩家明确选择 | 正面、背面、两面同时显示；可切换外层 |
| 64 × 32旧布局 | 仅经典 Classic | 旧布局左右肢体镜像；外层仅帽子，无现代独立左臂/左腿或全身外层 |

[官方皮肤介绍](https://www.minecraft.net/en-us/article/what-is-minecraft-skin)区分经典4像素手臂与纤细3像素手臂。Lua的2D拼接使用固定UV矩形和像素绘制；布局参考来自维护者的一手实现资料 [skinview3d](https://github.com/bs-community/skinview3d/blob/master/src/model.ts) 与 [skinview-utils](https://github.com/bs-community/skinview-utils/blob/master/src/process.ts)，并用原创编号像素核对。它们不是Mojang API文档；没有将这些渲染项目的代码、依赖或皮肤素材打入应用。

可以切换正面/背面、外层、透明棋盘/浅色/深色背景及2–12倍的有限整数缩放。预览不改变收藏图片；没有3D透视、姿势、光照或外层空间膨胀。像素透明保持原样，不填色、裁切或镜像后覆盖源PNG。透明数量和检查提示只作诊断，不证明官方服务接受，也不推断实际Java游戏怎样处理基础层透明。

## 支持的PNG范围

本版只接纳宽64、高32或64，8bit非交错的RGB、RGBA、灰度、灰度加透明度及调色板PNG。其他位深、交错图像、APNG动画、高清比例、Bedrock皮肤包或伪装成PNG的其他格式会明确拒绝或显示不支持，不自动转换为可用皮肤。

输入上限2MiB，最多1024个chunk；先核签名、IHDR、chunk边界/CRC/顺序和完整结束记录，再限制图像解压。IDAT有128KiB硬展开上限，还要与精确扫描行大小一致；无关附加信息不解压或交给预览。PNG结构依据 [W3C规范](https://www.w3.org/TR/png-3/)，上述尺寸和资源预算是Lua本地实现范围，不是官方上传限制。

解码固定使用 `pngjs@7.0.0`（MIT，安装跳过脚本），完整许可保留在[第三方声明](../THIRD_PARTY_NOTICES.md)和桌面bundle。检查结果规范化为无附加信息的8bit RGBA PNG，核对像素与摘要后供收藏和预览。源图、规范化像素与规范PNG分别有摘要；原用户文件不会被改写。PNG检查不等于图片来源、代码安全或游戏外观认证。

## 保存、导出和移出

图片准备能力有效120秒、只用于本次确认；普通预览或旧条目ID不能授权另一图片。保存前重验源与私有副本的身份、摘要和当前库；编辑、移出或导出绑定选中条目的新鲜revision。过期、源变化、库变化或结果不明时重新检查，不强制覆盖。

停止操作会请求取消，并等待实际worker、读取或原生窗口返回后才解除预留。停止请求不代表同步PNG解码已被即时中断；字节、尺寸和解压硬上限先约束其工作量。已经证明完成的提交不会因为迟到停止而显示假回滚，写入结果不明则保留资料并报错。页面关闭、查询或选择变化不接受旧结果，列表和详情读取也按操作ID串行处理。

导出通过原生保存窗口创建新的普通PNG文件，使用排他写入，不覆盖已有文件。导出的是检查后、去掉附加信息的规范化副本，不是原PNG字节级备份。移出收藏仅记录索引移出状态，受管图片blob与历史资料保留，占用额外空间；不会删除用户原图或重置账户皮肤。

## 库容量与故障边界

图库独立于实例、世界和账户，名称与标签不参与文件路径。显示列表不含原生路径、外部URL或完整图库图片；只返回所选图片的受限规范化data URL。没有URL导入、在线皮肤搜索、批量扫描、自动同步、账户上传/重置或披风管理。

| 范围 | 当前上限与处理 |
| --- | --- |
| 收藏记录 | 最多500条历史记录，移出条目也计入；不自动回收记录 |
| 规范化图片blob | 合计32MiB；移出收藏不删除blob |
| 活动索引 | 1MiB；坏索引不回退空库并覆盖 |
| 预览准备资料 | 最多64个目录、合计32MiB；当前临时文件只在身份和字节证据吻合时尝试清理，未知或历史预览保留 |
| 索引历史 | 最多2048次提交，控制凭据8MiB、全部历史128MiB；提交前预检旧备份、新快照和控制资料，任一容量先到均会停止 |
| 操作与返回 | 单worker、60秒合作式预算；每页24项、查询200字符，DTO上限512KiB |

索引提交保留已检查的旧快照、intent与完成凭据；启动检查历史链和普通文件范围，不重新hash全部旧备份载荷，也没有历史恢复或垃圾清理向导。索引结果、活动文件身份或提交归属不明，以及历史快照为符号链接或不受支持文件时，停止并保留资料，不自动修复或覆盖。不要把历史快照存在当作已经提供外观回退功能。

文件身份、独立读回与有限提交保护不承诺任意同用户系统调用竞态、跨卷/网络文件系统或断电耐久。通用应用退出仍不能据此声称等待所有IO结算。源码、原创PNG/文件测试、注入UI、原生IPC、真实OS窗口和实际游戏分别记录；本轮结果见[开发日志](devlog/0.14.0.md)与[独立审查](reviews/0.14.0.md)。
