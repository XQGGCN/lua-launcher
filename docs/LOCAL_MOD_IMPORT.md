# 导入本地模组

0.12.1 在“实例内容 → 模组”提供“导入本地模组”。它向明确的实例新增一个本地 `.jar` 文件，不替换、删除或自动启用已有模组，也不下载前置依赖。原有[模组声明与只读预览](MOD_DETAILS.md)仍是独立入口；只读预览结果不能直接授权导入。

## 操作步骤

1. 在桌面版中选择已经安装完成的目标实例，关闭所有使用该实例的游戏和服务端，并等待启动准备、文件操作、读取或设置保存结束。Lua 只能管理自身掌握的任务，不能代替你确认外部游戏已经关闭。
2. 在“导入本地模组”点击“选择本地模组 JAR”，选择一个普通 `.jar` 文件。选择文件、读取和检查期间会保持忙碌状态。
3. 在“确认导入到此实例”核对目标实例、游戏与加载器、`game/mods/文件名.jar`、大小、候选 Mod ID、检查提示和 SHA-512。声明中的名称由文件提供，不代表作者或站点认证。
4. 条件满足后，勾选“我已关闭所有使用此实例的游戏和服务端，并确认将此文件导入上方实例。”，再点击“确认导入到此实例”。确认约两分钟有效；过期、源文件、实例设置或现有模组集合变化后，需要重新选择并检查。
5. 等待“已导入……”回执。回执表示文件已经新增并完成本次读回核对，来源登记为本地文件；不表示模组已经运行或组合已经通过游戏验证。

“停止导入任务”发出取消请求后，界面仍需等待实际读取、文件选择或写入任务结算。停止请求不保证关闭系统文件选择窗口；若文件已经完成提交，迟到的停止请求不会把成功回执改成失败。切换实例后，旧任务结果不会显示成新实例的结果。

## 当前可以判断的兼容条件

本版只开放 **Fabric schemaVersion 1** 和明确 **Forge 实例中的 `javafml`** 有限导入；实例中能够展示 NeoForge 或 Quilt 声明，不等于可以导入它们。原版实例不能通过此入口添加启用模组。

| 声明 | 本版支持的范围 |
| --- | --- |
| Fabric | 明确的客户端或通用环境、数字发布版本，以及受支持的入口、Mixin 和访问扩展路径声明。数字精确条件、`>`、`>=`、`<`、`<=`、`=`、`*` 可解释；空格连接表示同时满足，数组表示满足其中一个。 |
| Forge | `javafml`，语言加载器版本按当前 Forge 主版本判断；数字精确区间如 `[47]` 或单个数字区间如 `[47,48)`。模组版本可使用主 Manifest 中明确的 `${file.jarVersion}` 替换。 |
| 依赖和冲突 | 重新检查当前游戏、加载器和已启用模组的明确版本及声明关系。禁用模组不满足必需依赖，`provides` 别名不被猜成具有可用依赖版本。 |
| Java | 当前导入流程不执行 Java 来测量实际运行时版本，也不把游戏清单要求当作测量结果。声明需要确认 Java 版本才能通过的条件会阻止导入。 |

预发布或构建后缀、Fabric 的 `^`、`~` 等未实现条件、Maven 软版本或区间并集，以及未知或无法解释的必要条件不会被猜成兼容。NeoForge、Quilt、混合声明、嵌套 JAR、JarJar、服务提供者、自定义语言适配器和其他未实现语义会阻止导入。没有强制绕过按钮或依赖求解器；提示不支持也不代表文件恶意。

Lua 会读取当前启用 `.jar` 和禁用 `.jar.disabled` 的声明，检查 Mod ID 与 Fabric `provides` 别名冲突，并复核文件名、禁用伙伴及历史下载登记中的同名记录。名称比较包含大小写与 Unicode NFC 规范化；不能通过换名或新增启用副本绕过已有禁用模组。历史站点记录仅用于冲突检查，不证明当前字节归属，也不会授权覆盖已有文件。

现有目录、声明、历史记录损坏、含糊、读取不完整或超过预算时，检查不能证明“没有冲突”。当前完整索引最多包含 256 个 JAR/禁用 JAR、累计 512 MiB，候选单文件最多 512 MiB，并有条目、元数据及时间预算；遇到限制会阻止本次导入。

## 文件检查与失败处理

导入检查会流式验证受支持 ZIP 布局中全部载荷的实际大小与 CRC，并计算整个 JAR 的 SHA-512；暂存后再独立读回、核对摘要、源文件身份和当前实例条件。ZIP64、加密、多卷及不受支持的布局不能作为通过检查的文件。这个过程不执行 JAR，但 **CRC 和摘要不证明代码安全、作者身份、数字签名或实际游戏兼容性**。应从自己信任的发布来源获取模组。

确认后，Lua 在实例的 `.mod-import-staging` 私有目录准备副本，只在目标仍为空且没有禁用伙伴时新增文件，并读回目标与完成凭据。只允许创建缺少的 `game/mods` 子目录，不会补造缺失的实例或游戏目录，不改写源 JAR、其他模组、世界或历史站点下载记录。

成功和失败的准备副本、凭据都会保留，占用额外磁盘空间；本版没有自动清理、续传或恢复向导。如果出现“本地模组导入结果需要人工检查”，请保留暂存目录、目标文件和日志，停止重复尝试，先检查结果。重启时会只读检查有限的事务凭据，对不完整、损坏或无法确定的提交结果阻止后续冲突操作；不会自动删除文件或回滚。正常完成后的玩家编辑或删除不会仅因历史摘要不同而永久锁住实例。

这些保护有明确提交边界，不承诺断电耐久、外部运行游戏时的一致性或任意外部程序同时修改文件的安全性。它们也不替代世界备份。

本文说明 0.12.1 的实现合同。真实操作系统文件选择窗口、第三方模组和游戏加载尚未由本版证据验证；原生 IPC、原创文件夹具、注入回调、构建和平台 CI 的执行范围分别以当前版本开发与审查日志为准，不能互相替代。
