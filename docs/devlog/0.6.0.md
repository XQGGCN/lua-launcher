## 玩家可见变化

从版本行“实例内容”或底部“内容”打开只读清单。四类分别对应当前实例的 `game/mods`、`game/resourcepacks`、`game/shaderpacks` 与 `game/saves`，只读取各目录的直接文件和文件夹。支持文件名搜索、按名称/修改时间排序、刷新、每页最多 100 条、四标签键盘切换和同页条目详情。

详情显示名称、相对路径、文件或目录类型、修改时间、普通文件大小及可关联的历史来源登记。目录大小显示“未统计”。“曾登记来源”不代表当前字节已校验；`.disabled` 仅表示文件名后缀，不代表游戏实际加载状态。世界清单不读取 NBT，游戏名称、版本、种子、模式、最后游玩时间等均未解析，修改时间不能当作游玩时间。

清单带读取时间、扫描警告与截断状态。搜索和排序只作用于已经读取的条目；截断或跳过条目时不把结果宣称为整个目录。安装期间拒绝扫描，运行中允许只读查看并说明文件可能变化。浏览器预览明确无法访问磁盘，不生成示例文件或数量。

## 实现与修复

- 扫描由 Core 按实例 ID 和固定分类决定路径，renderer 不能提交任意本地目录；返回结果再次检查实例与分类。
- 一层元数据扫描有条目数和时间预算，不解压、不执行 JAR、不读取世界 NBT、不递归计算目录大小。危险名称、链接、非常规条目或读取失败显示警告或错误。
- 模组来源仅从受限大小的既有登记记录关联；冲突或损坏记录不升级成可信来源。未把文件名匹配当作 hash 验证。
- 相同实例/分类的扫描去重，整体限制并发；退出取消扫描。实例开始安装时使既有扫描失效，即使安装在旧扫描返回前已结束，也不会发布混合时期记录。
- 打开文件夹的 App 回调返回实际 Promise，错误不再被上层吞掉；组件等待状态和实例请求序号守卫能处理晚到结果。
- 界面按请求序号及实例/分类键丢弃过期响应，加载、错误、空结果、截断和运行状态分别表达；只读清单不出现尚未实现的管理按钮。

独立扫描/Core 审查见 [0.6.0 审查](../reviews/0.6.0.md)，界面接线见 [0.6.0 UI 审查](../reviews/0.6.0-ui.md)。修复对应 REVIEW-060-01/02；本文不替代独立结论。
