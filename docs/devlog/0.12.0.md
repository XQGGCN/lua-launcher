# 0.12.0 开发记录

日期：2026-10-24。基线`6f2d3b1`（0.11.2），本地完成待本提交发行。新增已安装`.jar`/`.jar.disabled`的明确选择详情，以及按实例选择本地JAR的只读预览。没有本地模组导入、依赖求解、代码执行或真实加载认证；后续0.12.1单独实现add-only导入。见[用法](../MOD_DETAILS.md)与[格式依据](../MOD_METADATA_FORMATS.md)。

## 实现与范围

- 普通文件no-follow读取、现存祖先/目录及名称冲突检查、FD/path的BigInt身份前后复核，选中行按名称、大小与清单时间匹配。清单没有保存旧inode；开始观察前若文件已被换成相同清单字段，结果只能描述新鲜观察，不能冒充先前inode认证。viewId只读，不是导入能力。
- 有界ZIP中央目录/局部布局检查，只流式展开固定的Fabric/Quilt JSON、Quilt开发JSON5标记、Forge/NeoForge TOML与Manifest；校验这些条目的CRC/实际大小，外层文件流式SHA-512及来源复核。不提取或执行类、嵌套JAR、图标、URL；没有验证其他条目的CRC或JAR签名。未知/错误/不支持诊断与完整可用元数据分开。
- Fabric1、Quilt1声明、Forge/NeoForge多模组与依赖表分别投影；TOML使用准确锁定的`smol-toml@1.9.1`（BSD-3-Clause、Node>=18），跳过安装脚本。JSON拒重复键，语义标识不清洗成另一个有效值；对象、字符串、mod/dependency数量和DTO都有预算。JSON5只标为Quilt开发格式不支持，不新增Quilt实例。
- Manifest按字节续行，仅主节已知字段和可解释的`${file.jarVersion}`来源，其他节不替换主版本；签名或Main-Class等字段仅文字。依赖/范围不统一套npm SemVer或宣称满足。多加载格式分别显示，Forge/NeoForge关系保持未知；Fabric的匹配只指声明格式，未判断游戏、Java、运行侧或依赖。
- Core/main在首await前占用单实例读取与活动槽，全局最多两项；原生picker等待包含在预留内。精确取消等实际worker结算，更新/启动/文件写/改名/设置互斥，列表刷新、实例代次与退出使迟到结果失效。公开DTO逐层白名单，不含原生路径、FD或未来私有字段。
- 实例内容页新增“模组声明”：显式读取所选文件或本地JAR，展示名称/ID/版本/作者/许可/依赖/环境/别名/嵌套声明和外层摘要。无目录时本地预览仍可用且不创建目录；读取期间同实例后缀修改/刷新禁用，实例切换和停止隔离旧结果。

## 实际问题与修复

1. 独立实际P2：文本清理先移除控制/格式字符，再验证ID，导致`bad\u0000id`被改造成`badid`。已改为原始语义字段验证，Fabric/Quilt/TOML的ID、别名、依赖、语言加载器与版本字段不静默改义；两项受管回归和独立探针通过。
2. 集成者原生实际P2：生产清单用`new Date(info.mtimeMs)`，读取器误用会四舍五入的`info.mtime`，小数毫秒使普通已安装JAR被误拒。首次原生失败与直接生产`scanResourceInventory → inspectInstalledMod`红灯已保留；修复精确时间表达，新增真实生产组合回归，BigInt身份检查保持。旧单元夹具也误用了Date，已纠正；不能只用匹配错误实现的夹具代替生产合同。
