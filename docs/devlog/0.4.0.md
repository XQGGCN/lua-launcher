# 0.4.0 开发日志

日期：2026-10-21（Asia/Tokyo）；基准：0.3.0 / `5b39e227664d31dad9d97ae2924244fc2dc04273`。
关联：JAVA-001–017、JAVA-020，UI-006/007/008，AUTH-取消边界，RELEASE-版本一致性。功能矩阵按具体条目记录，未完成的管理能力不视为已交付。

## 玩家可见变化

安装或修复游戏时，按官方清单准备 Java；无匹配版本时从 Mojang 下载。设置页可提前安装 17/21/25；运行时列表包含来源和架构。下载任务跨页面可见，支持取消和重试。自动/手动切换保留手动路径，下载不会修改手动偏好或系统环境变量。

原有“只提示自行安装 Java”改为缺失时自动准备；手动路径无效仍报错。设置草稿切页保留，显式撤销恢复已保存值。

## 实现与故障恢复

运行时元数据、文件数/大小、HTTPS来源和逐跳重定向有界检查。常规文件先下载、验证和设权限，再生成限定在树内的合法链接。完整目录验证和真实探测后写receipt与原子提交；按内容hash及唯一ID保留不可变目录。发现损坏目录时不覆盖旧目录，重新安装并保留其他版本。共享任务按消费者取消；所有worker/probe退出后清理暂存。死进程遗留暂存可识别，活动或未知owner不自动删除；不宣传断点续传。

Core统一入口覆盖原版/加载器/整合包，加载器解析后、处理器前校验额外Java要求。旧安装记录缺component时从已校验官方游戏清单恢复。主进程在获取凭据前登记启动准备，取消/退出与账户代次在spawn前再次检查。

## 修复与审查

- 首次安装因Core与manager重复追加runtimes而失败：统一传入数据根，补真实manager的全新目录fixture。
- 提交事件后取消导致结果和目录不一致：提交前最后检查；原子rename成功作为完成边界，迟到取消不误报失败。
- 凭据等待阶段尚无取消控制器：新增LaunchPreparations，在凭据请求前登记；延迟凭据/退出回归阻止晚到启动。
- 活动任务事件导致历史快照整批丢失：按任务ID合并并保留事件新值。
- 设置页切换丢未保存草稿：首次打开后保留组件及草稿。
- 旧检测失败迟到后显示假错误：过期请求直接丢弃，不继续向子组件抛出。
- 表单重试、Dialog标题/焦点、下载tabs语义与键盘行为一起修正。

独立审查者及对应复核见 [审查记录](../reviews/0.4.0.md)，不把作者自测当独立批准。
