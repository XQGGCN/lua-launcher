# 0.6.1 开发日志

日期：2026-10-21（Asia/Tokyo）。基准为 0.6.0 提交 `17c4a16c24f04f2a7075f847262e4bc684889111`，开发分支为 `codex/resource-download-v0.6.1`。本版本尚未公开发布；官网和公开下载继续使用实际已发布的 0.3.0。

本轮推进 M3 的资源安装部分，关联 RESOURCE-002/005–007/009/010/013–015/019/021/025、MOD-017、UI-011/012、ARCH-003/006–009 和相关安全、发布要求。仅完成注明的资源包与 Iris / OptiFine 光影范围，不代表整项资源管理或 PCL / HMCL 功能对齐已完成。

## 玩家可见变化

新增“资源包与光影”入口，可在 Modrinth 与实验性 BBSMC 之间切换、搜索项目、选择目标实例和兼容发布。资源包按 `minecraft` loader 查询；本轮光影只接受发布声明的 `iris` / `optifine`，不会用实例的 Fabric / Forge 名称代替光影引擎。Canvas / Vanilla 等其他渲染方案、网盘或外站文件、不能安全自动处理的必需或不兼容依赖，保留官网获取入口。

选择完成后，主进程重新读取项目和版本，核对类型、来源、项目、版本、文件名及 SHA-512。接受明确的主 ZIP；无 primary 时只接受唯一主 ZIP，附带资源包文件不能作为主文件的退路。有效 ZIP 原样放入目标实例的 `game/resourcepacks` 或 `game/shaderpacks`，不解压、不执行资源，也不修改 `options.txt` 或渲染模组配置。完成状态明确为“已放入目录，尚未启用”；实际渲染前置和启用仍需按项目作者说明操作。

任务页显示真实下载、校验和提交进度，可取消；关闭选择窗口不终止后台任务。失败或取消后可重新选择目标与发布重试。已有同一版本、同一字节文件校验后复用；不同版本更新、同名不同内容或跨来源冲突不会自动覆盖。任务历史限当前进程，不承诺持久恢复或字节级续传。

安装来源与下载时的 hash、大小和日期记录在实例的 `managed-resources.json`，资源清单可关联该历史登记。清单本身仍不读取 ZIP 内容、不重新计算当前文件 hash；外部修改文件后，历史登记也不能证明现有内容完整或已启用。

## 文件事务与审查

- 元数据限定在当前来源 API，逐跳验证主机，使用 4 MiB 上限和严格 UTF-8；文件下载只接受该来源的 HTTPS CDN，拒绝验证网页、截断、大小或 hash 不符。
- SHA-512 必需；提供 SHA-1 时同时验证。ZIP 上限 512 MiB，文件名、目录祖先、链接和登记文件均受校验。
- 暂存下载和验证后，以不覆盖目标的文件提交及原子登记 rename 完成事务。成功登记后，迟到取消不把已提交安装改报为取消。
- 失败只回滚可确认由本任务创建且未被改动的文件；无法安全回滚时保留目标与恢复资料，并使实例进入需检查状态。既有用户文件和来源登记不被静默覆盖。
- 同一实例安装、启动、保存设置互斥，最多四项资源事务；取消仍等待 worker 结算后释放槽位。安装前后使旧库存扫描失效。
- 七项独立审查发现已修复：依赖字段类型绕过、合法 slug 误拒、流/句柄退出清理、同 inode 外部编辑的回滚保护、下载期间启动入口漏锁、其他实例完成导致内容页重挂载，以及真实 BBS 混合搜索/换行简介误拒。逐项证据见 [审查记录](../reviews/0.6.1.md)。
- 开发服务器忽略 `release`、`.local` 和 `dist` 等构建/验收输出，避免打包文件变化使正在验收的表单被意外刷新；这是开发体验修复，不是新增发行功能。
