# 0.6.2 开发日志

日期：2026-10-21（Asia/Tokyo）。基准为 0.6.1 提交 `5138dabd6677e4bdedd97d21e772e38a1a0f2b6f`，开发分支为 `codex/mod-toggle-v0.6.2`。本版本尚未公开发布，官网与公开下载仍为 0.3.0。

本轮完成 MOD-007 / MOD-008 的单文件禁用与恢复部分，以及相关 UI、互斥、文件保护和恢复检查。批量操作、删除、备份管理、模组元数据、依赖分析及实际加载判定仍未实现，不代表完整模组管理或 PCL / HMCL 功能对齐。

## 玩家可见变化

在实例内容页的“模组”详情，可检查当前文件并确认 `.jar → .jar.disabled`，或将 `.jar.disabled` 恢复为 `.jar`。检查预览显示实例、原名和目标名；确认前不改名。只支持已经安装完成且关闭游戏的 Fabric / Forge / NeoForge 实例，以及固定 `game/mods` 中的普通文件；手工放入、无来源登记的文件也可操作。非规范大小写后缀、目录和链接不提供此操作。

改名成功只表示这一个文件的名字改变，不表示模组已加载、依赖齐备或组合兼容。关闭依赖模组可能导致下次游戏启动失败，本轮不会自动联动其他文件。操作不联网、不解析或执行 JAR，不新建下载任务。文件名改变后刷新本实例清单并选中新条目；若当前搜索会隐藏新名字，会清除该搜索以显示结果。其他实例的分类与搜索保持。

历史 `managed-mods.json` 不随改名更新。禁用后的新名字不会通过去掉后缀来猜测来源，恢复精确原名后可重新关联原有历史登记；该登记仍不是当前内容或加载状态的认证。

安装模组时，对所选项目和必需依赖检查新文件及同来源项目的历史文件名。存在禁用伙伴、大小写/Unicode 名称冲突或同时存在两个名字时，在下载文件和创建暂存目录前拒绝；升级不能悄悄把用户禁用的旧版变成启用新版。

## 文件保护与审查

- 主进程重新检查文件身份和目录，签发至多 32 个、有效期 120 秒的确认令牌。令牌绑定实例、明确目标状态和检查时的文件身份；首次提交即消费，不通过重放反向操作。
- 同实例的安装、启动准备、运行和保存设置互斥，主进程取账户凭据前也检查文件操作锁。实例变化、退出或本次操作开始/结束会使旧令牌和旧清单失效。
- 固定目录内先建立不覆盖目标的硬链接，再删除原名字；原名字成功删除是提交边界。提交前取消安全回滚，提交后的迟到取消不会反向移动文件。
- `.mod-toggle-<UUID>/intent.json` 保存受限恢复证据。外部编辑、替换或无法安全回滚时保留文件与记录，禁止后续启动、安装和实例设置写入；即使 `launcher.json` 保存失败，内存安全门仍有效。
- 重启仅清理身份一致、恰好保留原名或新名的明确记录；双名、缺失、坏记录、链接或不明确身份继续阻断。缺 intent / 空标记也不猜测为安全，需人工检查后重启。不是任意断电恢复承诺。
- 三项 P2 已修复：并发检查的普通忙碌误标为恢复损坏、清理 intent 时未保护同 inode 的外部编辑，以及恢复错误未及时通过 state 事件通知界面。来源、复现和修复后证据见 [独立审查](../reviews/0.6.2.md)。
