## 问题

在原生产下载函数的隔离故障测试中，网络内容 SHA-256 正确，但一次文件写入只写了部分字节时，函数仍返回成功。固定 `.partial` 文件还会复用并截断已有文件；并发失败可能删除另一个任务的资料。异常返回后响应流没有完整取消和释放。原 main 更新入口在下载等待时允许检查结果改写共享 `updateInfo`，曾在结果变成 null 后崩溃。

旧问题均用临时原创字节和注入 HTTP/文件系统重现，没有运行安装程序。独立审查者另外从 `git show` 精确载入原函数和入口代码验证，测试壳不等于原生 Electron IPC。

## 实施范围

- 下载改为每个任务独立私有目录、排他写入、短写循环、磁盘大小与 SHA-256 独立读回；只有校验后的文件才交给下一步。
- 限制本仓库 GitHub 源地址及每跳 HTTPS；文件上限、总超时、闲置超时和无进展限制分别约束，响应和读锁在结束时释放。
- AppImage 使用同目录私有暂存，保留独立旧文件副本；发布前再次核对原目标与目录身份。无法确认结果时要求检查恢复资料，不自动猜测回滚。
- 更新检查使用代次隔离，玩家确认绑定主进程签发的选择 ID。安装等待期间固定版本、摘要和动作，不接收迟到检查覆盖。
- 桌面 IPC 统一计数直到实际工作结算；Core 更新预留同时检查启动、后台 Java、文件任务、排队保存和游戏退出维护。更新期间拒绝新的写入/启动，取消请求不提前释放工作锁，安装程序启动失败不会自动退出 Lua。

成功和失败的私有资料均保留，没有自动清理或续传；AppImage 会额外保留一份完整旧包。空间检查不是空间预留，不承诺断电耐久或防任意同用户恶意文件置换。退出只请求取消，没有新增 Electron 等待所有 I/O 完成的退出握手。
