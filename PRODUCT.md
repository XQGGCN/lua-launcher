# Lua · 未央 — product scope

## Product direction

- Independent open-source Minecraft Java desktop launcher targeting Windows, macOS and Linux.
- Prioritize installation and launching. PCL and HMCL are feature references.
- Practical, compact, light desktop UI: concise navigation, aligned version rows, account and Java summaries, and a persistent launch action.
- Brand: Lua · 未央. Use independent names, artwork and interface assets.
- Source distribution through GitHub; an optional website can provide downloads and documentation.

## Implementation scope

Electron, React and TypeScript. Original UI and launcher integration; no copied PCL, HMCL or Modrinth implementation or brand assets.
The current local version is 0.7.1 Alpha: modern Vanilla, Fabric, Forge and NeoForge installation; isolated instances; verified automatic Mojang Java provisioning and manual selection; per-instance Java, memory, JVM and game-window overrides; read-only one-level instance inventories, bounded selected-world metadata and explicit seed reveal, validated local manual complete directory backups, with separately confirmed single-mod filename disable/restore actions; verified resource-pack and Iris/OptiFine shader ZIP placement; task progress; logs; Microsoft account flow; and Modrinth / experimental BBSMC discovery and `.mrpack` installation. Public downloads remain 0.3.0 until the new commits pass their own CI and release checks. Broader feature parity remains a roadmap.

Version 0.3.0 implements 19 official Modrinth mod categories, corresponding BBSMC Chinese search facets, and the category-filter UI. Real optimization-category searches on both sources returned matching category tags for the first 20 results checked per source. Categories describe upstream project tags, not locally inferred mod behavior; this sample does not validate every category or mod combination.

Gameplay requires an authenticated Microsoft account with Minecraft Java entitlement and profile verification. Offline identities and their launch path were removed in 0.2.2 and remain unavailable.

Automatic memory is the default. It combines physical RAM, a fresh runtime/OS availability estimate, the game workload hint and the selected Java architecture. The runtime's `process.availableMemory()` is preferred, with `os.freemem()` as a fallback. Reclaimable-memory and process-limit accounting depends on the runtime and platform. Both automatic and manual allocations preserve OS and Java native headroom, are capped again before launch, and refuse an allocation below the minimum budget. The saved manual preference is retained when switching modes.

Version 0.7.0 adds on-demand read-only world details from an explicitly selected `level.dat` or `level.dat_old`. Files never fall back, merge or restore automatically. Default DTOs contain no seed; explicit reveal rereads the same fingerprint under a two-minute, instance/source-bound capability. Signed 64-bit seeds and ticks remain decimal strings. Missing, mistyped, unsupported or over-budget fields remain unknown instead of deriving defaults from the instance version. Error-state instances can be read without triggering recovery cleanup or launcher-state persistence.

The original parser validates big-endian NBT with bounded bytes, depth, tags, arrays, strings and cooperative time. Canonical Java modified UTF-8 deliberately rejects some noncanonical forms tolerated by Java readUTF. Gzip input/output and safe ancestor/file identities are checked before and after parsing. Minecraft 26.1 nested difficulty/hardcore fields are supported within the selected file, but migrated independent seed/clock files are not read. World backups/restores, edits, icons, regions, player data, datapacks and full-version compatibility remain out of scope. World-format evidence is from official notices and maintainer schemas; all test worlds are original fixtures, not actual game-generated samples.
